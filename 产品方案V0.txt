# 财经博主日报聚合站 —— V1 产品方案 & 执行手册

> 定位：**个人自用**的财经/宏观博主观点聚合工具。主信源为你截图中的微信公众号博主（华尔街见闻、券商中国、泽平宏观、韩秀云讲经济、李大霄、打板宝哥、荀玉根思考、李迅雷金融与投资、孟岩、EncounterAlpha 等），目标是每天早上花 5 分钟看完"今天这些人都说了什么、谁的观点变了、谁跟谁矛盾"。
> 本文档你可以直接分段喂给 Codex / Claude Code 执行。

---

## 一、先把"信源怎么拿"说清楚

这是整个项目里最不确定的一环，直接决定项目能不能稳定跑下去，所以放在最前面讲。

微信公众号没有对第三方开放的抓取接口，纯页面爬取有两个现实问题：**不稳定**（页面结构、反爬策略会变）和**账号/IP 有被限制的风险**（如果抓取行为过于频繁或规律）。三条路径给你对比：

| 方案 | 稳定性 | 自动化程度 | 你的操作成本 | 建议 |
|---|---|---|---|---|
| **A. 半自动转发**：你在微信里刷到文章，随手转发到自建的 Telegram Bot / 企业微信机器人 / 一个专属邮箱，后端只解析这个链接的正文 | 高（几乎不受平台策略变化影响） | 中（抓取和总结全自动，只有"发现文章"这一步靠你） | 每天 1-2 分钟，顺手转发几条 | **V1 首选**，个人使用场景下性价比最高 |
| **B. 自建 RSSHub 实例走微信路由** | 低-中（依赖第三方 key/账号，容易失效） | 全自动 | 前期配置麻烦，后期偶尔要修 | 可作为 V1.5 的实验项，不作为唯一依赖 |
| **C. 页面直接爬取（公众号历史消息页 / 文章页）** | 低（反爬策略随时变，且有一定封号/限流风险） | 全自动 | 前期开发量最大 | 不建议作为主力方案，尤其是个人项目没必要为了全自动而冒风险 |

**我的建议**：V1 用 **A 方案打底**（可靠、几乎零风险），同时把"文章来源"这一层做成一个独立的 ingestion adapter 接口——以后如果 B 方案跑通了，或者你想接入 X 的账号，直接加一个新的 adapter 就行，不用改下游任何逻辑。这样"直接爬"这条路留了口子，但不会让整个产品的可用性绑死在一个不稳定的抓取脚本上。

X（Twitter/洪灝这类账号）如果要接入，**用官方 X API**（有付费档，几十个账号的时间线读取成本不高），比爬页面稳，值得的话可以单独开一期。

## 二、比"聚合摘要"更丰富的产品功能（脑暴，供你挑）

聚合+摘要是地基，下面这些是能让它从"信息搬运工"变成"真正有洞察"的方向，按实现难度排了序：

**容易加（V1-V2 就能做）**
- **分歧/反差标注**：同一天多个博主谈同一件事（比如"降准""地产"），自动列出谁看多、谁看空，一眼看出共识 vs 分歧
- **关键词追踪**：设定几个你关心的词（"降息""外资""地产""AI算力"），每天统计提及频率，画一条时间线，看话题是在升温还是冷却
- **原文溯源**：每条摘要下面直接挂原文链接，你要深读随时点进去（这个也顺便规避了"复制别人观点当自己的"的问题）
- **每周/每月综述**：日报之外自动生成一份周报，把这一周里各家观点的变化脉络理一遍，比每天看碎片更有knowledge compounding的感觉

**中等难度（V2-V3）**
- **个人批注/收藏**：看到觉得有意思的观点，一键收藏+写点自己的想法，相当于给自己攒一个"财经笔记本"，过一阵子回看自己当时怎么想的
- **多空情绪指数**：把当天所有博主的观点做个粗略的情绪打分，画一条"市场情绪温度计"曲线，纯粹好玩但也挺直观
- **观点回溯准确度**：记录每个博主某天说过的判断（比如"看多黄金"），几个月后对照实际走势，给一个粗糙的"命中率"——这个对判断"这个人到底靠不靠谱"很有价值，也是你产品未来最有差异化的点之一
- **语音播报**：生成当天日报的 TTS 音频，通勤路上听，对"每天固定习惯"这件事帮助很大

**更进阶（有余力再做）**
- **RAG 问答**：攒了几个月数据之后，可以直接问"过去三个月大家对地产的看法怎么变化的"，跳出"看日报"变成"查资料库"
- **双语对照**：如果后面接了 X 上的双语博主（比如洪灝），中英对照展示，正好呼应你最初想看"反差"言论的初衷

我建议 V1 先把"聚合摘要 + 分歧标注 + 关键词追踪 + 原文溯源"这四个做扎实，这几个组合起来已经比单纯的信息流有价值很多，其他的留到确认自己真的每天会用之后再加。

## 三、V1 技术架构

```
① 信源接入层 (ingestion/)
   └─ adapter: forward_bot        —— 接收你转发的文章链接（Telegram Bot 或邮件），抓取正文
   └─ adapter: manual_import      —— 兜底：命令行/网页手动粘贴一条文章
   (预留) adapter: x_api          —— 未来接 X 官方 API
   (预留) adapter: rsshub         —— 未来实验公众号 RSS

② 存储层 (storage/)
   SQLite（个人用够了，不需要一上来就上 Postgres）
   表：articles(id, source, author, title, url, raw_text, published_at, fetched_at)
       summaries(article_id, summary, tags, stance, divergence_note)
       digests(date, content_md)

③ 处理层 (pipeline/)
   - 去重（按 url + title 简单去重即可）
   - 调用 Claude API 做单篇摘要（3-4 句话 + 打标签：主题/多空倾向）
   - 每日跑一次"横向比较"：把当天所有摘要一起喂给 Claude，生成"共识 vs 分歧"板块
   - 生成当日日报 Markdown

④ 展示层 (web/)
   - 每日日报页 + 历史归档 + 按博主筛选 + 按标签筛选
   - Next.js，起步用 SQLite 直接读，不需要额外后端服务

⑤ 调度
   - 本地/VPS 上用 cron，每天固定时间跑一次 pipeline，生成当天页面
```

**技术栈**：Python（ingestion + pipeline，脚本类任务写起来快）+ Next.js（展示层）+ SQLite + Claude API（摘要与分析）。

## 四、页面设计方向

给 Codex/Claude Code 做前端时，直接把下面这套"设计令牌"带过去，避免它默认生成那种一眼假的 AI 模板风（暖米色+衬线大标题+赤陶色强调色的组合，或者纯黑+荧光绿这种，都刻意避开）。

**设计概念**：把"每日财经日报"当成一本正在被写的**账本/笔记**来做，而不是新闻聚合站。核心意象是"手写批注 + 数据台账"的混合体——正文是干净的排版，但"分歧""关键词趋势"这些你自己关心的洞察点，用像是手写批注或红笔圈注的视觉语言标出来，呼应"这是我自己在读、在做记号"的私人属性。

- **色板**：
  - 底色 `#EFEAE0`（偏灰调的浅纸色，不是流行的暖米黄 #F4F1EA，刻意压低饱和度更像旧纸而不是"设计感米色"）
  - 正文墨色 `#1F1C18`（偏暖的墨黑，不是纯黑）
  - 强调色·分歧标记 `#8B2E1F`（暗砖红，做圈注/下划线用，克制地用，不做大面积背景）
  - 强调色·共识标记 `#3A5A40`（暗松绿）
  - 辅助色·数据/图表 `#2B4C6F`（藏蓝，用于关键词趋势图）
- **字体**：
  - 标题：思源宋体 Noto Serif SC（衬线，有分量但不做超大 hero 字号，避免"杂志封面感"）
  - 正文：Noto Sans SC
  - 数据/日期/标签：等宽数字（如 JetBrains Mono 的数字部分），让日期、频次这些数字对齐工整，有"账本"的秩序感
- **布局**：
  - 顶部不做大 hero，直接是"今日日报"的日期+一句话摘要（像翻开笔记本的第一行）
  - 正文用单栏为主、克制的分栏，段落间用细线分隔而不是卡片阴影
  - 每条博主观点前用一个小圆点+作者名，"分歧"话题单独在文首/文尾出一个横向对比条（谁多谁空，一眼看清）
  - 历史归档做成"翻页"式而非无限下拉，强化"每天一页"的仪式感
- **签名元素**（这个页面会被记住的一个东西）：**"分歧刻度尺"**——每个话题横向比较板块用一条像老式温度计/刻度尺的 SVG，两端标"看多/看空"，每个博主的头像小圆点落在刻度尺上对应位置，一眼看出今天大家的分布，而不是列表堆砌。
- **克制原则**：不用渐变、不用大面积阴影卡片、动效仅限于"新的一天/新一条摘要"轻微淡入，不做花哨滚动特效。响应式做到手机能舒服读（毕竟通勤/睡前刷的场景更多）。

## 五、执行阶段拆分（可直接分段喂给 Codex / Claude Code）

**阶段 0 —— 项目脚手架**
> 指令示例："创建一个 Python + Next.js 混合项目骨架，目录结构如下：ingestion/、pipeline/、storage/（SQLite schema）、web/（Next.js）。先只搭骨架和 SQLite 建表脚本，不写业务逻辑。"

**阶段 1 —— 信源接入（forward_bot）**
> 指令示例："写一个 Telegram Bot，接收我转发的文章链接，抓取该 URL 的正文（标题、正文、发布时间、公众号名），存入 SQLite 的 articles 表，做 URL 去重。"

**阶段 2 —— 摘要与分析 pipeline**
> 指令示例："写一个脚本，读取当天新增的 articles，调用 Claude API 对每篇生成：3-4句摘要、主题标签（房地产/降息/A股/海外市场等，允许多个）、多空倾向（看多/看空/中性）。再对当天所有摘要做一次批处理调用，生成'今日共识与分歧'板块（哪些话题多数人一致，哪些话题出现明显分歧，分歧双方是谁、说了什么）。结果写入 summaries 表和 digests 表。"

**阶段 3 —— 日报生成 + 关键词追踪**
> 指令示例："基于 digests 表生成当天的 Markdown 日报，包括：今日摘要列表（按分歧板块置顶）、关键词频次统计（对比过去7天变化趋势）。"

**阶段 4 —— 前端展示**
> 指令示例："用 Next.js 实现日报站点，读取 SQLite 数据。页面结构：首页=最新日报，/archive=历史归档（按日期翻页），/tags/[tag]=按标签筛选，/authors/[name]=按博主筛选。视觉设计按以下令牌执行：[粘贴上面'四、页面设计方向'整段]。"

**阶段 5 —— 调度自动化**
> 指令示例："写一个 cron 任务配置，每天早上7点依次跑：pipeline 处理当天新文章 → 生成日报 → 触发 Next.js 静态页面重新构建。"

每个阶段做完你可以先跑起来看效果，觉得不对随时喊停调整，不用一次性把 V1 全部需求都堆给它，分阶段执行出错也好定位。

## 六、后续可以聊的方向

等 V1 跑顺了、你确认自己真的会每天打开看，可以再讨论：
- 要不要接入洪灝这类 X 账号（涉及 X API 费用和双语摘要 prompt 设计）
- "观点命中率追踪"怎么设计打分规则（这个可能是产品最有意思、最值得做深的方向）
- 要不要做成 Telegram/邮件早报推送，而不是每天主动打开网站
